AgentStride is a local-first runtime for coding agents that do long, multi-step work. The goal lives in Git, the progress in SQLite. When sessions end, context evaporates, or workers crash, the run picks up exactly where it stopped. AgentStride 是一个本地优先的运行时，为做长周期、多步骤工作的 coding agent 而建。 目标存在 Git 里，进度存在 SQLite 里。 会话结束、上下文蒸发、worker 崩溃，run 都会从停下的地方精确地继续。

01why为什么

How long agent jobs fail长任务失败的常见方式

A chat session is the wrong container for a long goal. Contexts expire, processes die, plans drift, and a task queue assumes work finishes or fails cleanly. Long agent work does neither. 一个 chat session 是承载长期目标的错误容器。上下文会过期，进程会死掉，计划会漂移， 而任务队列假设工作要么干净地完成，要么干净地失败。长任务两者都不是。

The goal outgrows the session 会话装不下一个长期目标

A week of work doesn't fit in one context window, and an LLM that plans is allowed to change its mind. AgentStride holds the goal as versioned data: growing it takes an explicit, approved revision, never a silent rewrite. 一周的工作装不进一个 context window，而会做规划的 LLM 本来就允许改变主意。 AgentStride 把目标存成 版本化数据：修改目标需要一次显式、经审批的 revision， 绝不是悄悄重写。

The worker dies halfway worker 中途挂掉

Every attempt runs under a transactional lease with a signed capability token. When the lease expires, the work is recovered and handed to another worker. A stale worker that comes back late is fenced off, not trusted. 每次 attempt 都在事务化租约和签名能力令牌之下运行。租约到期， 工作被恢复并交给另一个 worker。迟到归来的过期 worker 会被围栏挡住，而不是被信任。

Retries corrupt state 重试污染状态

Tasks retry behind persistent timers, and every retry is a new, explicitly numbered attempt in history. Nothing overwrites what already happened. 任务在持久定时器后面重试，每次重试都是历史里一条新的、 显式编号的 attempt。没有任何东西会覆盖已经发生的事。

Nobody can explain the run 没人能说清这次 run 做了什么

State and events commit together in one transaction. History can always rebuild and verify the current state. Recovery is derived, not guessed. 状态与事件在同一个事务里一起提交。历史永远可以重建并校验当前状态， 恢复是推导出来的，不是猜出来的。

02features特性

What AgentStride providesAgentStride 提供的能力

Each mechanism exists to make runs recoverable and history verifiable. 每个机制都为了让 run 可恢复、历史可校验。

🌿

Versioned goals版本化的目标

The goal is tasks and blocks edges as JSONL in Git. A revision is immutable; growing the goal means proposing a new one. 目标就是 Git 里 tasks 与 blocks 边的 JSONL。revision 不可变， 让目标生长就意味着提出一个新的 revision。

🎟️

Transactional leases事务化租约

Claims and leases commit in one transaction. Signed tokens fence stale attempts before they can overwrite newer results. 认领与租约在同一个事务里提交。签名令牌把迟到的过期 attempt 挡在围栏外， 让它无法覆盖更新的结果。

⏰

Durable retry timers持久重试定时器

Failed work parks behind a persistent timer and comes back ready without blocking unrelated branches. 失败的工作挂在持久定时器后面，到点自动回到 ready，不阻塞任何无关分支。

📜

Append-only history只追加的历史

Events and state commit together. The log replays to rebuild and verify materialized state, explicitly and idempotently. 事件与状态一起提交。日志可以重放，显式、幂等地重建并校验物化状态。

◇

The goal is a DAG目标是一张 DAG

Chains, diamonds, fan-in: ready work derives from authoritative state, and independent branches run concurrently under separate leases. 链、菱形、扇入：ready 工作从权威状态推导而来，独立分支在各自租约下并发执行。

🗺️

Execution-map console执行地图控制台

A read-only web UI replays any run: branching DAG with wave labels, attempt lifecycles, and the live event stream. 只读的 Web UI 重放任意一次 run：带波次标注的分支 DAG、attempt 生命周期、 以及实时事件流。

🔌

CLI + MCPCLI + MCP

as is the stable human surface with JSON output; as mcp is a local stdio MCP server for agent integration. as 是面向人和自动化的稳定入口，带 JSON 输出；as mcp 是本地 stdio MCP 服务器，供 agent 集成。

🧪

Deterministic evaluator确定性评估器

as-eval exercises retries, timeouts, handoffs, recovery, and plan evolution with fake workers, no model API key needed. as-eval 用假 worker 演练重试、超时、交接、恢复与计划演化， 不需要任何模型 API key。

03how it works工作原理

Goals are stored as data. Execution is recorded as a log.目标以数据形式存储。执行以日志形式记录。

AgentStride treats the goal as data and execution as an append-only state machine. A reconciler joins the two without rewriting completed history. AgentStride 把目标当作数据，把执行当作只追加的状态机。 调和器（reconciler）把两者对齐，而不重写已完成的历史。

plan layer计划层

The goal is a Git object目标是 Git 里的对象

Tasks and blocks edges, exported as JSONL. A revision is immutable; changing the goal means proposing and approving a new revision. tasks 与 blocks 边，导出为 JSONL。revision 不可变； 修改目标意味着提出并批准一个新的 revision。

runtime layer运行时层

The progress is a SQLite log进度是 SQLite 里的日志

An append-only event log plus materialized task state. A run executes exactly one plan revision, deriving ready work from authoritative state. 只追加的事件日志，加上物化的任务状态。一次 run 只执行一个 plan revision， ready 工作从权威状态推导。

reconciler调和器

Change without rewriting变更而不重写

Compares the current revision to the run and computes discovered, ready, invalidated, and superseded work. Completed tasks are never silently rerun. 把当前 revision 与运行中的 run 对比，算出 discovered、ready、invalidated、 superseded 的工作。已完成的任务绝不会被悄悄重跑。

Kill it on Friday. Rerun on Monday. Completed work is never repeated, in-flight work is recovered behind its lease, and the revised plan slots in without rewriting history. 周五 kill 掉，周一重跑。已完成的工作绝不重复，进行中的工作随租约恢复， 修订后的计划直接接入，不重写任何历史。

05see it run看它运行

The web console replays every run.Web 控制台重放每一次 run

The web console never mutates state. It replays history: the execution map draws the plan as a branching DAG, task nodes drill into their attempt lifecycle, and the event panel streams the append-only log. Web 控制台从不修改状态。它重放历史：执行地图把计划画成分支 DAG， 任务节点可以下钻 attempt 生命周期，事件面板流出只追加日志。

The read-only console replaying a finished run: four scheduling waves, three branches executed in parallel by three workers, and one branch that failed once and recovered behind a durable retry timer. 只读控制台重放一次完成的 run：四个调度波次、三个分支由三个 worker 并行执行、 一条分支失败一次后挂在持久重试定时器后面恢复。

Parallel branches并行分支

A release DAG with one root, three parallel branches, a three-way join, and a release gate. One branch fails on purpose, parks behind a retry timer, and recovers without blocking the others. 一条发布 DAG：一个根、三条并行分支、一次三路汇合、一道发布闸。 一条分支故意失败，挂到重试定时器后面，在不阻塞其他分支的情况下恢复。

06quick start快速开始

One binary and one SQLite file on your machine.运行只需要一个可执行文件和一个 SQLite 文件

Nothing to deploy and nothing to administer. The whole runtime state is one local SQLite file. 不用部署服务，也不用运维数据库。运行时的全部状态就是本地的一个 SQLite 文件。

as · agent-stride
# build the CLI
$ cargo build --bin as

# plan the work: versioned in Git
$ as init
$ as add "Design storage"
$ as add "Implement storage"
$ as link <implement-id> --blocks <design-id>

# run it: derived, leased, fenced
$ as ready --json
$ as claim-next --actor worker-a --json
# 构建 CLI
